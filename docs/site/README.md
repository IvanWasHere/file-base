# FileBase website

The Jekyll site published to GitHub Pages at
<https://ivanwashere.github.io/file-base/>: a landing page and a user guide.

## GitHub Actions

| Workflow | When | What it does |
| --- | --- | --- |
| [`pages.yml`](../../.github/workflows/pages.yml) | Pull requests touching `docs/site/` | Builds the site and checks it: every guide page is in the sidebar (`scripts/check-nav.rb`), and no internal link, image or anchor is broken (html-proofer). Publishes nothing. |
| | Push to `main` touching `docs/site/` | The same checks, then deploys to GitHub Pages. |
| [`screenshots.yml`](../../.github/workflows/screenshots.yml) | By hand: Actions → Screenshots → Run workflow | Regenerates the guide and/or README screenshots on a macOS runner and opens a pull request with them. Fails if any scene fails, and attaches what it saw. |

One-time repository setup:

- **Settings → Pages → Build and deployment → Source: GitHub Actions**, for the deploy.
- **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**, for the screenshots pull request.

To run the same checks locally before pushing:

```bash
ruby scripts/check-nav.rb
bundle exec jekyll build --baseurl /file-base
bundle exec htmlproofer _site --disable-external --swap-urls '^/file-base/:/'
bundle exec jekyll build      # back to a root-relative build for local serving
```

## Run it locally

```bash
cd docs/site
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve      # http://127.0.0.1:4000/
```

Or build once and open `_site` with any static server (e.g. VS Code Live Server):

```bash
bundle exec jekyll build
```

## Layout

| Path | What |
| --- | --- |
| `index.html` | Landing page |
| `guide/*.md` | Guide pages — add a page here **and** to `_data/nav.yml` (CI checks both) |
| `_data/nav.yml` | Sidebar order and the Previous / Next links |
| `_layouts/`, `_includes/` | Page chrome |
| `assets/css/site.css` | All styling, in the app's Nocturne palette; dark by default, light under `prefers-color-scheme` |
| `assets/img/guide/` | Screenshots generated by `scripts/capture.mjs` |
| `assets/img/showcase/` | Copies of the README images in `docs/screenshots/` |

## Screenshots

Guide screenshots are generated, not hand-taken, so they can be redone when the
UI changes. See the header of [`scripts/capture.mjs`](scripts/capture.mjs): it
drives `npm run dev:mock` with Playwright, so every image shows the same fake
`/Users/dev` and nothing private.
