# FileBase website

The Jekyll site published to GitHub Pages at
<https://ivanwashere.github.io/file-base/>: a landing page and a user guide.

`.github/workflows/pages.yml` builds and deploys it on every push to `main`
that touches `docs/site/`. One-time setup: **Settings → Pages → Build and
deployment → Source: GitHub Actions**.

## Run it locally

```bash
cd docs/site
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve      # http://127.0.0.1:4000/
```

Or build once and open `_site` with any static server (e.g. VS Code Live Server):

```bash
bundle exec jekyll build
```

## Layout

| Path | What |
| --- | --- |
| `index.html` | Landing page |
| `guide/*.md` | Guide pages — add a page here **and** to `_data/nav.yml` |
| `_data/nav.yml` | Sidebar order and the Previous / Next links |
| `_layouts/`, `_includes/` | Page chrome |
| `assets/css/site.css` | All styling; dark by default, light under `prefers-color-scheme` |
| `assets/img/guide/` | Screenshots generated by `scripts/capture.mjs` |
| `assets/img/showcase/` | Screenshots of the real app (copies of `docs/screenshots/`) |

## Screenshots

Guide screenshots are generated, not hand-taken, so they can be redone when the
UI changes. See the header of [`scripts/capture.mjs`](scripts/capture.mjs): it
drives `npm run dev:mock` with Playwright, so every image shows the same fake
`/Users/dev` and nothing private.
